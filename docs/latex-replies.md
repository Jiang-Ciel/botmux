# 飞书最终答复中的 LaTeX

普通 CLI 最终答复（含 Pi 的结构化 bridge 输出）和 `botmux send` 的 Markdown 卡片正文，会把闭合的 `$…$`、`$$…$$`、`\(…\)`、`\[…\]` 公式在本地转换为 PNG，再通过当前飞书应用上传。公式不会发给第三方渲染网站；历史、原生答复和导出的 Markdown 仍保留原文。

渲染使用 MathJax 的 base/ams 包与现有可选 `@napi-rs/canvas`。支持常见分式、根号、求和、上下标和 `aligned` 环境。不支持外部资源、HTML、链接和自定义宏；失败时显示 LaTeX 代码块，不丢弃公式。

边界：

- 简单行内公式优先转换为可复制的 Unicode 文字（如 `i`、`K=1`、`Fᵢ`、`xₜ`、`xᵢ²`、`α`），原句、列表、强调和已有换行保持不变，不插入图片或额外换行。仅转换有精确字符映射的小语法子集；复杂下标如 `p_{t,i}`、分式、根号、矩阵、字体/重音命令仍用图片，不通过删除命令或括号猜测含义。
- 复杂行内公式显示成独立图片，显式块公式即使简单也保持图片布局。图片按真实 PNG 尺寸的 1/2（2x 清晰度）显示，不铺满卡片；长公式按比例缩小到最大 560px 宽、600px 高。透明背景、无圆角，可点击预览原图。
- 只处理最终答复，不在流式进度卡和工具过程面板中上传公式。
- 自定义 JSON 卡片、受管会议输出和历史 adopt 前导不做额外公式上传。
- fenced/indented code、inline code、Markdown 链接、转义美元、普通金额、未闭合公式保持原样。
- 单次最多转换 128 个公式，每个最多 2048 字符；超出部分保留原样。图片限制为 2400×1200 像素（另加边距），限制 SVG 大小与宏展开次数。
- 没有可选 canvas 原生依赖的平台降级为源码；Linux 单文件二进制包含现有 canvas native，需同时做真实渲染与编译态验证，不能只依赖 CLI smoke。

示例：

```markdown
由 $x_i^2$ 可得：

$$
\frac{1}{n}\sum_{i=1}^{n} x_i^2
$$
```

卡片布局示意：

```text
由 xᵢ² 可得：
[公式图片：分式 × 求和表达式]
```

测试：`test/reply-math.test.ts` 校验 PNG 签名、尺寸及非空像素；`test/bridge-final-output-retry.test.ts` 用真实最终答复组件及假飞书上传验证 Pi 和另一个 CLI 的投递卡片。
